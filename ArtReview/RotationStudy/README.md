# 50 PPU 组件旋转小样

打开 `index.html` 即可离线使用。浏览器需支持 WebGL。文件已内嵌精灵与模型数据，不请求网络。

## 使用

1. 先看 22.5° 与 45°，对比枪管、锯齿和接口。
2. 点击“播放旋转”，可选 15 / 45 / 90 度每秒；暂停后滑动角度。
3. 切换单独检查狙击枪或链锯，另一件保留初始装配角度。
4. 关闭辅助标记看纯美术，开启标记检查连接轴和发射点。
5. 细节放大只扩大已渲染的结果，不改变低分辨率目标；小屏幕可横向滚动单张画面。

左侧直接在 600×600 分辨率渲染；右侧在 300×300 渲染，再最近邻放大两倍。世界视野均为 6×6 格，素材 50 PPU、总缩放 1。浏览器建议使用 100% 缩放。高 DPI 屏幕或浏览器缩放可能改变最终物理屏幕像素的映射，但两侧仍用同一显示尺寸比较。

## 数据来源与限制

模型为禁军、陷阵核心、厚实护甲、狙击枪、链锯、刀锋。素材 Pivot、槽位位置、安装角度、组件旋转偏移、连接偏移、枪口偏移从 Unity 资源导出，没有重新手调。

这是按原始挂点相对安装姿态旋转的美术检查，不执行 WeaponModule 的自动瞄准与近战动画，也不运行碰撞、伤害或寻路。正式代码的瞄准使用世界角度；本页角度是可控的相对检查角。完整一圈用于观察接口，不意味着正式武器必须无限转动。

浏览器使用 WebGL 最近邻纹理采样、透明混合、无抗锯齿。Unity 导出了相同场景的 22.5°、45° 参考图，以及七个角度下六个图层的变换坐标。不同渲染后端在采样边界仍存在细微差别，页面不是正式游戏画面的逐像素保证。

为固定对比，样例按底盘、核心、护甲、狙击枪、链锯、移动组件递增排序。正式 MechUnit2D 给组件设置相同 sortingOrder，实际遮挡还受排序模式与相机等影响。本页的明确排序没有写回正式工程。

## 检查结果

- 六张素材为 50 PPU，五个部件符合槽位类型，示例组件缩放均为 1。
- 42 组角点、旋转轴、发射点计算与 Unity 结果最大误差约 1.4e-7 世界单位。
- 22.5° 时，按 RGB 各通道允许 8/255 误差计算，浏览器与 Unity 的前景像素一致率：直接模式约 99.78%，低分辨率模式约 97.38%。剩余差异不应被表述为零。
- 交互检查覆盖完整旋转复位、单件旋转、播放/暂停、角度预设、标记、细节放大与窄屏布局；无浏览器运行时异常。
- 原始记录见 `checks.txt`、`review-checks.txt`、`unity-browser-comparison.json`。

## 发现与后续方向

1. 两种采样都能保留绕轴拼装逻辑，无需每个方向单独画图。低分辨率模式让最终像素方格一致，但不能消除旋转轮廓跳变。
2. 狙击枪和链锯的 MuzzleOffset 均为零，WeaponModule 会把发射点放在转轴上。狙击枪应另行校准画面枪口与发射位置；本次没有修改。
3. 需要明确武器旋转到躯干前后时的遮挡规则。固定顺序只是本样例用来隔离渲染差异的约定。
4. 建议先保留直接旋转路线，再由用户实际播放比较是否接受斜角变化。若严格要求统一屏幕像素方格，再选择低分辨率路线，并修整关键细线。

正式工程的素材、导入设置、场景、预制体和存档均未修改。没有在用户工作编辑器里切换 Play。

工具：`Tools/ArtReview/RotationStudy.cs` 只在隔离 Unity 工程执行；它建立临时场景、不保存资源。`build_rotation_review.py` 打包页面；`check_rotation_review.mjs` 使用独立 headless Chrome 检查。不要在有未保存场景的工作编辑器执行导出入口。
