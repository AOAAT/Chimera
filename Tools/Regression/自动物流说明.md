# 自动物流第一版

## 游戏内使用

1. 进入殖民地场景，会在可达的空地生成“初始补给仓库”，接收旧的全局资源、未装备组件和底盘。不会额外赠送资源。
2. 点击屏幕顶部“物流管理”（也可从全局仓库的“物流 / 资源”进入）。
3. 在“搬运居民”页为至少一名地图上的居民开启搬运。建筑员工先下岗才能参与；开启搬运不会自动遣散固定岗位。
4. 工厂下单。材料不足也可以排队；居民会自动取货、补料，开工时才消耗材料。
5. 成品先进入工厂出货区，搬运入库后才能在装配界面使用。组件编号、品质和词条全程不变。
6. “仓库与暂存区”可查看容量、入库预留和收纳设置；“货物位置”包含背包、工厂与遗留货物；“运输任务”显示当前阶段。
7. “新建仓库”进入现有网格放置流程，右键取消。仓库当前采用临时箱子图标，建造费用暂为零，未替游戏决定最终资源配方。
8. 点击地图仓库，底部面板提供容量和库存入口；有货物或入库预留时不能拆除。

项目现有的 R 补给、Y 组件调试入口仍可使用。新资源会进入可收纳的仓库，溢出部分留作待收纳货物。调试不是正式采集玩法。

## 规则与边界

- 默认居民不自动开启搬运，背包容量 20；资源每单位占 1 容量，组件/底盘每件占 1 容量。是原型值，不是最终重量平衡。
- 工厂原料区默认 2000 容量、出货区 8 件。并行订单先检查整份配方的暂存容量，避免多个半成套材料互相堵塞。
- 每条产线独立收料与扣料。开工预留一个出货位置，已开工订单即使暂停仍占用该位置。
- 取消订单沿用原有全额退料规则，包括已开工订单；实际材料留在工厂/背包，等待搬运退回，不直接增加全局数字。
- 手动移动/入驻优先于物流，已取货物不会删除。关闭搬运时背包保留货物，再开启后先退货。
- 居民进入建筑、死亡、放逐或实体被移除后，货物保留在最后位置的遗留货物容器，由其他搬运工收回。
- 寻路请求每个调度周期最多 4 次；失败有冷却；移动受阻 8 秒后释放执行居民并重试。
- 默认仓库 10000 容量，旧档迁移时必要时扩大初始仓库，避免迁移丢失库存。
- “拒收资源/组件”控制未来入库，不会销毁或自动转运仓内已有物资。
- 资源总 HUD 目前显示可用仓储资源，不含已经预留、运输中或进入工厂的材料。
- 本轮接入工厂的资源、组件和底盘物流。逻辑配件仍沿用原有库存；建造与机甲组装尚不产生物理送料任务，仓间主动调拨、个人口粮、采集、重量差异尚待后续。
- 现有生产加速和并行产线规则保留；没有凭本次开发修改整体生产时间平衡。

## 实现入口

- `Assets/Scripts/物流/LogisticsData.cs`：位置容器、货物键、任务和可序列化 DTO。
- `LogisticsManager.cs`：唯一位置台账、任务派发、来源/目的地预留、生产收料、退料与恢复。
- `WarehouseBuilding.cs`：运行时仓库、初始仓库位置选择；沿用现有建筑占地和放置检查。
- `LogisticsPanelUI.cs`、`WarehouseUIModule.cs`：自动生成的管理页和建筑详情。
- `ResidentEntity` 复用现有 Rigidbody2D 移动；`ResidentData` 保存搬运开关和容量。
- `PlayerInventoryManager.ComponentInventory` 仍是永久组件档案库，位置由物流台账记录，不再把档案存在等同于仓库可用。
- `GlobalResourceManager` 的增减资源 API 接入位置台账；原有字段保留为可用库存汇总。

## 回归运行

继续使用 README.md 的隔离项目方法，将 `LogisticsRegressionChecks.cs` 放到副本 `Assets/Editor`，入口为：

```text
Unity.exe -batchmode -projectPath <隔离副本> -executeMethod LogisticsRegressionChecks.Run -logFile <日志>
```

不传 `-quit` 或 `-nographics`。输出位于副本 `LogisticsResults`。脚本测试会临时更改库存、生成居民并重载场景，只应在副本执行；完整读档测试通过内存快照，不写入用户默认存档文件。

端到端运输使用真实物理移动；部分取消、满载、死亡遗留和阻路边界用确定性状态布置，不代表大规模居民压力测试。
